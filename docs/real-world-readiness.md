# 真实世界可用性拆分方案

## 1. 业务拆分（从 MVP 到可上线）

### A. 安全闭环层（必须先上线）
- 入口承接（entry/triage/intake）
- 红旗识别 + 冲突识别 + 高危接管
- 审计留痕
- 回流后再评估

上线门槛：高危不漏接管、非法状态跳转可告警、关键节点可审计。

### B. 服务执行层（第二阶段）
- 观察等待/服务承接
- 随访任务和提醒
- 检查结果回流

上线门槛：任务可追踪、回流可追踪、异常可重试。

### C. 价值转化层（第三阶段）
- 价值确认
- 付费资格 gating（value_eligible / value_blocked）
- 首单触发与订单状态回写

上线门槛：商业表达永远晚于安全判断，且高危/冲突自动阻断。

## 2. 真实世界保障清单
- 医疗边界：AI 不独立下诊断结论，关键决策可人工复核。
- 技术边界：contracts + mocks + adapters 分层，避免绑定外部供应商。
- 运营边界：高危 SLA、消息失败告警、支付回调对账。
- 合规边界：最小授权、日志脱敏、审计可追溯。
